## 一、产品定位

**一句话定位**
> 面向企业与政企场景的**合规统一 AI 网关**，统一接入多类大模型，提供路由容灾、用量计量、审计留痕与私有化交付能力。

**目标用户**
- 企业 IT / AI 中台团队（要统一接入多家模型、做用量与成本治理）
- 政企客户（有数据不出域、等保合规、信创适配要求）
- 行业 ISV 集成商（需要稳定的模型供给和合规底座）

**核心价值主张**
| 维度 | 价值点 |
|------|--------|
| 统一 | 一次接入，多模型可调用，降低多供应商重复集成成本 |
| 容灾 | 路由策略化（主备、溢出、降级），自动故障切换 |
| 留痕 | 用量、成本、审计记录可追溯 |
| 私有化 | 支持内网 / 离线 / 信创部署，按合规要求交付 |

**品牌调性**
- 暗色主基调（`#0a0b0d` 背景），金色 / 红色高亮点缀
- 字体：Noto Sans SC（正文）、Source Serif 4（标题）、IBM Plex Mono（数字 / 代码）
- 中英双语，i18n 切换在导航栏右上角
- 文案非常克制、反复强调"合规"、"审慎"、"按正式协议"——典型 B 端 / 政企产品话术

## 三、核心功能（6 大产品模块）

### 01 统一 API
- **能力**：OpenAI 兼容接口（`/v1/chat`），多模型适配
- **价值**：降低多供应商重复集成成本，调用方不改业务代码即可切换底层模型
- **可参考设计点**：接口命名、鉴权方式、错误码体系应兼容 OpenAI 标准

### 02 路由引擎
- **能力**：基于策略的选路（成本 / 延迟 / 可用性 / 合规边界）
- **支持策略**：主备、溢出、降级（fallback / overflow / degraded）
- **可视化**（UI 示意）：路由列表展示每路模型的 `primary / fallback / overflow / cross-border` 状态、实时延迟、健康度、错误状态
- **可参考设计点**：路由策略 DSL、健康度探测、熔断降级阈值、自动 failover

### 03 密钥与配额
- **能力**：按项目 / 团队 / 业务系统配置独立密钥、限流、额度、可用模型范围
- **权限模型**：RBAC + 最小权限
- **可参考设计点**：
  - 密钥命名约定（如 `sk·app / sk·agent / sk·test`）
  - 配额展示：百分比进度条 + 状态色（ok / warn / error）
  - 多维度归属（按密钥、按模型、按团队）

### 04 计费与成本
- **能力**：多模型、多渠道调用统一计量与费用拆分
- **可拆分维度**：按项目、按密钥、按业务线
- **可视化**：成本拆分面板（如 <PRIVATE_PERSON> / <PRIVATE_PERSON> / <PRIVATE_PERSON> / 合计 ¥1,284）
- **可参考设计点**：账单颗粒度（按请求 / 按 token / 按带宽）、对账能力、发票与抵扣

### 05 可观测性
- **能力**：调用日志、用量趋势、成功率、延迟分布
- **核心指标**：QPS（请求/分钟）、P95 延迟、当日成本、可用率
- **可参考设计点**：
  - 14 天用量趋势柱状图
  - 峰值日高亮
  - 路由状态事件流（切换事件、错误事件）
  - 告警接入

### 06 私有化部署
- **能力**：内网部署、离线封闭、信创适配
- **可参考设计点**：
  - 部署形态：客户机房 / 专有云 / 内网
  - 网络：支持离线 / 物理隔离
  - 数据：语料、推理请求、业务数据全部留存在指定环境
  - 信创：国产芯片 + OS + 数据库 + 国产大模型

## 九、可借鉴的 8 个设计要点

1. **"统一 API"作为入口价值**：用 OpenAI 兼容接口降低切换成本，是模型聚合层最有效的价值主张。
2. **路由引擎可视化**：把抽象的"容灾切换"做成路由表 + 状态条 + 切换事件流，让运营人员能感知、能追责。
3. **密钥命名空间化**：`sk·app / sk·agent / sk·test` 这种命名约定比 UUID 更易读、易管理。
4. **多层级成本拆分**：按模型 + 按密钥 + 按团队三维度拆分账单，是企业财务对账刚需。
5. **模型成熟度标签**：`active / soon / on-demand` 比单纯列表更能传达能力边界和合规风险。
6. **交付双轨制**：在线 / 私有化分开，PMF 和商业模式都不同，要做不同的销售流程。
7. **极简暗色 B 端风**：不用堆特效，靠衬线 + 等宽 + 网格构建专业感，政企客户买单率高。
8. **合规话术前置**：每一段功能描述都加一句"以正式协议为准"，对 B 端 / 政企是减负，对监管是护身符。

## 十、如果你要做一个类似产品，最值得先做的 3 件事

1. **先确定"统一 API"协议层**——是 OpenAI 兼容？还是自研？这是平台型产品的协议地基。
2. **先把"路由 + 密钥 + 计量"三件套做扎实**——这是网关的最小可用形态，比"接入多少模型"重要得多。
3. **先把"用量 + 成本"两块仪表盘做漂亮**——B 端客户决策链上，财务和运维是绕不开的两个角色，他们看的就是这两个面板。
