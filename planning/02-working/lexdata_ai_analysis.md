# lexdata-ai 现网分析：对 LLM-portal 的产品与工程启示

> 来源：Codex session `<SECRET>` 对一套 lexdata-ai 1.0.4 现网实例的只读检查（2026 年 8 月 12 日）
> 研究范围：运行形态、主要功能、数据库统计、接口鉴权和容器权限；未读取密钥、提示词或对话正文
> 定位：本文件是 `planning/02-working/` 下的设计输入，不修改或替代已冻结的用户故事基线 r2

## 一句话结论

lexdata-ai 验证了「模型映射 + API Key + 用量计量 + 调用审计」在真实部署中会成为长期使用的核心，而模型容器管理与应用商店未体现出同等实际价值。对 LLM-portal 最有价值的不是复用其源码或扩大 MVP，而是吸收其运行数据带来的数据模型经验，并避免其管理面鉴权、凭据存储和宿主机高权限部署风险。

## 现网观察

### 部署与产品形态

- Python 3.12 + Flask + SQLAlchemy + SQLite，原生 HTML/JS 管理界面。
- 单容器、单 SQLite 持久库，对外提供管理控制台和 OpenAI 兼容 API。
- 支持本地模型、远程模型、API Key、用量统计、请求审计、系统状态和应用商店。
- 镜像内存在可审阅的发布源码，但没有 `.git`、README、许可证或可确认的上游仓库，因此不能作为 LLM-portal 的代码来源。

### 安全边界

该实例的管理容器具有接近宿主机 root 的能力：

- root 用户运行；
- host network 和 host PID；
- 可写 Docker socket；
- 可写挂载宿主机 `/opt`、Docker 配置和模型目录；
- 管理界面可以操作应用容器和打开容器终端。

同时，源码未体现统一的管理 API 鉴权中间件，部分路由依赖各自检查，部分系统或商店接口可匿名访问。实例还存在内置默认管理员凭据、无盐 SHA-256 密码哈希，以及 API Key/上游凭据明文字段等问题。

这些风险并非 LLM 网关的必要代价，主要来自把网关、宿主机模型编排和通用容器管理放进同一个高权限控制面。

## 与 LLM-portal r2 的对应关系

| 现网证据 | 对应基线 | 对设计的含义 |
|---|---|---|
| 密钥、日用量和审计数据持续积累 | US-06、US-07 | 密钥治理、计量和可筛选调用日志应保持 MVP 高优先级 |
| 模型配置为空但历史仍有价值 | US-03、US-04、US-07 | 调用日志必须保存不可变的路由与计量快照，不能依赖当前配置反查 |
| 审计正文带来隐私和存储负担 | US-12、C7 | 正文默认关闭、按密钥开启、限期保留的方向正确 |
| 单容器 + SQLite 可以承载长期网关数据 | US-10、C3、C6 | 继续采用单实例 Compose + SQLite 的 MVP 交付形态 |
| 高权限管理容器扩大失陷影响 | US-10、C3 | 网关必须使用最小权限部署，管理面安全应进入验收条件 |
| 本地模型和商店使用量为零 | Non-Goals | 不把模型容器编排或应用商店加入 MVP |

## 建议吸收的设计

### 1. 不可变调用快照

调用元数据不能只保存外键。每次请求至少固化以下快照字段：

- 对外模型名、实际供应商和实际模型名；
- 选中的上游与主备尝试链；
- fallback 原因和每次尝试的状态；
- 入站协议、出站协议和转换器 ID/版本；
- System Prompt 策略 ID/版本；
- 内容优化规则版本；
- 上游 usage、估算标记和价格版本；
- 虚拟密钥的稳定 ID 与显示名称快照，不保存密钥正文。

删除或修改密钥、路由、模型、供应商及价格配置时，不级联删除或改写历史调用记录。这样 US-07 的成本与故障解释在配置变更后仍然成立，也能承载 US-04 的切换事件流和 C4 的转换审计。

### 2. 管理面安全验收条件

建议在下一次基线修订或技术设计中，把以下内容作为 US-10 的明确验收条件：

- 首次启动只允许进入初始化流程，强制设置管理员密码，不交付通用默认凭据；
- 密码使用 Argon2id 或同等级自适应哈希；
- 管理 API 统一经过默认拒绝的鉴权中间件，不允许每个路由自行决定；
- 管理会话、虚拟调用密钥、US-12 数据访问凭据属于三个独立鉴权域；
- 虚拟密钥只保存带服务端 pepper 的哈希和可识别前缀；
- 上游凭据使用主密钥加密保存，日志、错误和导出均不得回显；
- 默认非 root、只读根文件系统、最小 Linux capabilities；
- 禁止 host PID、host network、Docker socket 和无关宿主机目录挂载；
- 管理控制台与数据 API 支持独立监听地址或反向代理访问控制。

如果未来确实需要本地模型生命周期管理，应拆成独立、可选的特权 agent，通过窄接口与网关通信；不能提升主网关容器权限。

### 3. 对话正文与调用元数据分离

US-12 的正文保存建议采用与调用元数据分离的存储边界：

- 调用元数据始终按 US-07 保存，正文仅在对应密钥显式开启时写入；
- 请求和聚合后的完整响应压缩、加密存储，通过调用 ID 关联；
- 保留期清理只删除正文，不破坏用量、错误和路由审计；
- 流式响应的聚合与持久化在客户端转发链路之外执行，失败不得中断已经完成的客户端流；
- SSE 事件包含稳定事件 ID，支持 `Last-Event-ID` 断线续传；
- REST/SSE 过滤条件、授权范围和日志展示采用相同的密钥/模型权限语义；
- 控制台展示正文存储量、最早到期时间、清理状态和持久化失败数；
- 日志与指标不记录正文、Authorization header、上游凭据或完整虚拟密钥。

### 4. 运维控制台聚焦网关状态

系统状态页可以借鉴，但指标应围绕 LLM-portal 的职责：

- 上游健康、成功率、超时率和 P50/P95 延迟；
- 429/5xx/协议转换错误分布；
- fallback 事件和主备尝试结果；
- 按密钥/模型/时间的请求、Token、成本和缓存 usage；
- SQLite 文件大小、正文存储量、清理任务和备份状态。

GPU、模型下载、容器终端和通用应用编排不属于主控制台。

## 明确不采纳

1. **不复用源码**：缺少可确认的许可证和版本历史，法律与可维护性边界不成立。
2. **不建设应用商店**：与统一 AI 网关目标正交，并要求过大的宿主机控制权限。
3. **不在主网关管理模型容器**：本地推理服务作为普通 HTTP 上游登记即可。
4. **不引入多用户/RBAC**：r2 的 C2 仍是单管理员；安全强化不等于扩大账号体系。
5. **不增加 Embeddings、Rerank 或图像生成入口**：继续遵循 r2 Non-Goals。
6. **不把本次观察直接写入 r2**：它是设计证据；任何用户故事或约束变化都应走下一版基线批准。

## 建议优先级

| 优先级 | 动作 | 落点 |
|---|---|---|
| P0 | 设计不可变调用快照及配置删除语义 | 数据模型、US-04/07、C4 |
| P0 | 冻结管理面鉴权、凭据保护和最小权限部署要求 | US-10、部署设计 |
| P0 | 分离调用元数据与可过期正文存储 | US-12、C7 |
| P1 | 定义 SSE 断线续传和正文持久化失败语义 | US-12 外部消费接口 |
| P1 | 设计网关导向的系统状态与存储状态指标 | US-07、US-10 |
| 不做 | 模型容器管理、应用商店、宿主机终端 | MVP 范围外 |

## 证据限制

- 结论来自一个实例在单一时间点的只读观察，不能代表 lexdata-ai 的全部部署或后续版本。
- 历史用量能够证明网关能力曾被实际使用，但不能仅凭数据库记录推断用户满意度或未使用功能的长期需求。
- 未验证外围防火墙、反向代理或默认管理员密码是否已修改，因此安全结论描述的是应用与容器暴露的能力和潜在影响，不断言现网已经发生未授权访问。
- 未读取对话正文、提示词、密钥值或上游凭据；本文也不记录相关敏感数据。
