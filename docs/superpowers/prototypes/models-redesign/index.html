模型管理弹窗重设计 · 三个方案

均为可交互高保真原型（真实设计系统壳 + mock 数据）：打开后弹窗/抽屉自动弹出； 点选端口会自动探测（三个方案一致），点选上游 id 自动带出对外名； 「其他端口…」可演示探测失败后的手填降级。列表里的「刷新上游 / 删除」也都可点。

推荐

方案 A · 列表弹窗 + 独立添加弹窗

「模型」打开纯管理列表（不再混排表单）；点底部「+ 添加模型」切到独立添加弹窗， 加完自动回到列表。管理与创建彻底分离，每个弹窗只干一件事。

 对比

方案 B · 单弹窗双 Tab + 真步进条

一个弹窗两个 Tab：已注册模型 / 添加模型。添加 Tab 用设计系统的 .pf-steps 三步条（选端口→选上游模型→起对外名），步骤状态随操作真实推进。

 对比

方案 C · 抽屉式

右侧 600px 抽屉：上半列表、点「+ 添加模型」在下方展开添加区， 添加时仍看得到已有模型作参照。纵向滚动承载更多模型。

后台操作均为 mock：添加/删除/刷新只改内存数据，刷新页面即复原。
