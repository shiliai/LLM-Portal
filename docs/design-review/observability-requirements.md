# Observability Dashboard 需求交接记录

> 状态：原型设计暂停，等待新的设计负责人确认视觉和交互方案。
> 本文记录当前对用户目标的理解，不能视为已经批准的最终 UI 规格。

## 用户目标

远程模型网关需要一个统一的管理站点。首屏是汇总仪表盘，数据来自真实 VPS 和四个真实推理节点（其中两台是 GB10 / DGX）。页面应持续更新，不刷新页面，图表容器保持稳定，只替换数据。

总览和节点性能都需要自动刷新，默认间隔 10 秒，并允许切换刷新间隔。总览支持时间窗口、节点、模型、Key 等维度组合筛选；筛选后同一张综合仪表盘更新，不能把每个节点的完整仪表盘纵向堆叠在总览中。节点性能页面可以按节点查看详细指标。

站点中已有的管理页面需要放在同一套视觉和交互体系中：请求与用量、模型部署、告警与设置、站点与公钥、分组、模型与别名、用户 Key、MCP 管理、安全设置、我的用量等。

## 总览页必须表达的内容

- 综合实时输出速度和趋势；
- 活动请求、排队请求和容量使用；
- 输入 Token、输出 Token、缓存读取 Token；
- 今日请求、成功率、失败数；
- 节点健康和采集链路状态；
- 综合 KV Cache、GPU、内存等资源指标；
- 时间窗口、节点、模型、Key 的组合筛选；
- 自动刷新开关、刷新间隔、最近更新时间；
- 无数据或指标缺失时显示明确的 `—` 或空态。

总览中选择单个节点时，综合卡片应变成该节点的汇总视图；选择全部节点时显示跨节点聚合值。总览标题不需要出现“综合实时性能”这类重复文案。

## 节点性能页必须表达的内容

节点页可以展示逐节点详情，但仍应支持节点筛选和时间范围：

- 输出 Token/s；
- 输入 Token/s / Prefill；
- 活动请求和排队请求；
- KV Cache 占用率及命中率（数据存在时）；
- MTP/TAR 或推测解码指标（数据存在时）；
- 统一内存使用量和可用量（数据存在时）；
- GPU 活跃度、温度和功耗（exporter 未提供时显示 `—`）；
- 运行时、节点地址、连接状态、最近采集时间；
- 吞吐和资源趋势。

真实节点没有 exporter 指标时必须显示 `—`，不能伪造为 0。当前真实链路包含 `gb10-dgx-a-llm`、`gb10-dgx-b-llm`、`dell-shili-7960-llm`、`m2s2NasUbuntuVM-shili-dev-llm`。

## 请求与用量详细页

此前的逐请求详细页需要保留，并与汇总趋势同页或通过清晰 Tab 进入。至少包括：

- 时间；
- Key / 用户；
- 模型和节点；
- 请求端点；
- 读 Token（输入）；
- 写 Token（输出）；
- 缓存 Token；
- 首字延迟和总时延；
- 成功/失败状态及错误说明；
- 搜索、状态/模型/端点筛选、刷新、导出和分页。

用量汇总可参考 Sub2API Usage Records 的信息密度：顶部 KPI、时间范围、粒度、分布表、趋势图和底部逐请求表。

## 视觉和交互参考

Sub2API 仅作为后台信息架构和信息密度参考，不复制其品牌或页面。可借鉴：

- 稳定的侧栏和页面标题层级；
- 顶部 KPI 卡片；
- 筛选和操作工具栏；
- 分布统计和表格；
- Tab、分页、导出、刷新、详情展开；
- 深色导航与浅色内容区的对比。

最终视觉由新的原型设计负责人确认后再实施。

## 当前已经完成的生产部分

PR #104 分支已经包含：

- `/usage` 的节点、模型、Key 过滤；
- 节点过滤可通过 deployment 关系解析；
- Dashboard 指标直连失败时回退 VictoriaMetrics；
- 总览趋势图和自动更新；
- 节点性能页面和统一导航；
- 总览默认 10 秒刷新，并支持 10/15/30/60 秒；
- 版本/build 标识。

生产已在 `vps-tencent-tokyo` 部署并验证过原有三节点 `up=1`；GB10 / DGX 双节点 agent 的部署配置已补齐，待目标节点执行部署后再以真实指标验收。生产 UI 仍应依据批准的原型重新整理页面结构和文案。

## 验收条件

1. 8765 原型所有导航页都有非空内容，切换不会出现空白页。
2. 总览是一个综合仪表盘，节点筛选改变同一套卡片数据，不堆叠三个节点仪表盘。
3. 节点性能页能展示上述指标，缺失指标显示 `—`。
4. 请求与用量包含汇总和逐请求明细，读/写/缓存 Token 可见。
5. 自动刷新默认 10 秒，可选间隔，页面不刷新。
6. 原型确认后再更新生产；生产验收必须使用真实节点和真实 VictoriaMetrics 数据，不能以 mock 作为证据。
