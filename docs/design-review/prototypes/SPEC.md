# 统一可观测性原型 · 设计规格（issue #106）

> 本文件是高保真原型的数据与功能规格。评审结论：**两版合并为单一原型，
> 深浅双主题可切换**（顶栏主题切换按钮，localStorage 持久化，支持 ?theme=light|dark）。
> 浅色主题：浅色内容区 + **浅色侧栏**、白色卡片、靛蓝强调（原方案 A 的经典后台气质）；
> 深色主题：深色面板 + 青色遥测强调（原方案 B 的指挥中心气质）。
> 布局结构统一（窄侧栏 + 顶部状态条），仅配色随主题切换；ECharts 图表配色随主题重渲染。
>
> 原型为**单文件 HTML SPA**（CSS/JS 全部内联），通过 ECharts 本地副本渲染图表：
> `vendor/echarts.min.js`（HTML 中用相对路径引入）。界面语言：中文。
> 所有数据为 mock，但必须真实可信、内部一致。

## 总览页（核心页，最高保真度）

顶部筛选工具栏（一行或两行）：
- 时间窗口：15分钟 / 1小时 / 6小时 / 24小时 / 7天（默认 1小时）
- 节点：全部节点（默认）/ 四个节点单选
- 模型：全部模型 / 各模型
- Key：全部 Key / 各 Key
- 自动刷新开关（默认开）+ 间隔选择 10s（默认）/15s/30s/60s + "最近更新 HH:MM:SS"
  + 下次刷新倒计时 + 手动"刷新"按钮
- 变更任一筛选：同一套卡片与图表就地更新（重新生成/聚合 mock 数据），
  **不刷新页面、不重建图表 DOM**（ECharts 实例复用，只 setOption）。

KPI 卡片行（至少 7 张）：综合输出速度 (tok/s，带迷你趋势)、活动请求（含排队数）、
今日请求、成功率（含失败数）、输入 Token、输出 Token、缓存读取 Token。
选"全部节点"显示跨节点聚合；选单节点时同组卡片变成该节点汇总。

图表区：输出速度趋势折线（全部节点时按节点分色/堆叠）、容量使用（活动+排队 vs 容量，
可用面积图或仪表盘）、资源概览（KV Cache 占用率 / GPU 活跃度 / 内存占用，按节点条形或卡片）。

节点健康与采集链路表：节点、运行时、地址、连接状态（up）、最近采集时间（几秒前，随刷新更新）、
exporter 覆盖情况（完整/部分）。标题不得出现"综合实时性能"这类冗余文案。

## 节点性能页

节点筛选 + 时间范围。每个节点一块详情区（或按筛选显示单节点）：
- 输出 Token/s（当前值+趋势图）
- 输入 Token/s · Prefill
- 活动请求 / 排队请求
- KV Cache 占用率 + 命中率（m2s2 节点命中率显示 `—`）
- MTP/TAR 推测解码接受率（gb10、m2s2 显示 `—`，dell 显示 ~62%）
- 内存/统一内存：已用 / 可用（GB）
- GPU 活跃度 %
- GPU 温度（°C）与功耗（W；exporter 未提供时显示 `—`）
- 元信息行：运行时版本、节点地址、连接状态、最近采集时间
- 吞吐与资源趋势图

## 请求与用量页

上半部分（用量汇总，参考 Sub2API Usage Records 的信息密度与布局）：
顶部 KPI 行 + **维度筛选栏**（评审结论：汇总页必须可按各维度筛选，筛选后整组仪表盘联动刷新）：
- 维度筛选：模型 / 分组 / Key / 节点 / 端点 下拉（默认"全部"）+ 重置按钮；
- 时间范围（近1小时/今天/近24小时/近7天）+ 粒度切换（按小时/按天）。
筛选条件作用于同一批明细记录，KPI、三个分布面板、Token 趋势全部从筛选后的
记录集实时聚合更新（筛选的维度自身面板保持可选值完整，如筛选"模型=X"时
模型分布面板仍显示全部模型的占比上下文，或按产品直觉处理，但必须自洽不死锁）。

汇总区核心是一套 **2×2 分布仪表盘网格**（复刻 Sub2API Usage Records 的结构，
费用类字段替换为私有网关语义：请求数 / 读 Token / 写 Token / 缓存 Token）：
1. **模型分布**：左侧环形图 + 右侧明细表（模型、请求数、Tokens、读/写/缓存），
   表格上方 Tab 切换 按 Tokens / 按请求数；行可展开（>）显示该模型按节点的拆分。
2. **分组/Key 分布**：环形图 + 明细表（分组或 Key、请求数、Tokens、读/写/缓存），
   Tab 切换 按分组 / 按 Key。
3. **端点分布**：环形图 + 明细表（/v1/chat/completions、/v1/completions、/v1/embeddings），
   Tab 切换 按 Tokens / 按请求数。
4. **Token 用量趋势**：多系列折线/面积图——输入、输出、缓存读取 Token（左轴），
   缓存命中率虚线（右轴 %），随粒度切换按小时/按天。
所有分布图与表格随时间范围/粒度联动更新。

下半部分（逐请求明细，可用 Tab "汇总 / 请求明细" 或同页分区）：

明细区参照 Sub2API Usage Records，表格上方必须有**统计仪表盘条 + 过滤器行**：
- 统计仪表盘（4-6 个小型统计卡，随筛选/搜索实时联动更新）：当前结果请求数、成功率
  （含失败数）、读 Token 合计、写 Token 合计、缓存 Token 合计、平均首字延迟、平均总时延。
- 过滤器行：时间范围（快捷：近1小时 / 今天 / 近24小时 / 近7天，加自定义起止）、
  Key 下拉、模型下拉、节点下拉、端点下拉、状态下拉、搜索框、重置按钮。
- 任一过滤条件变化时，统计卡与表格同时更新；导出 CSV 导出当前筛选后的结果集。

表格列：时间、Key/用户、模型、节点、端点、读 Token（输入）、写 Token（输出）、
缓存 Token、首字延迟 (ms)、总时延 (ms)、状态（成功/失败+错误说明，失败行可展开看错误详情）。
工具：刷新、导出 CSV（真实触发下载）、分页（每页 10/20/50，页码可点）。
mock 生成 ≥120 条明细，含 ~4% 失败
（如 `context length exceeded`、`upstream timeout`、`model overloaded`）。

## 其余管理页（中等保真，内容必须真实可信）

- **模型部署**：节点×模型的部署表（状态、权重/priority、今日请求、健康检查），"刷新模型"按钮。
- **站点与公钥**：站点表（名称、WireGuard IP、分组、模型数、状态）+ 访问公钥卡片（创建/吊销）。
- **分组**：分组列表（default、研发、数据分析），各组 Key 数/站点数，创建/重命名/删除入口。
- **模型与别名**：别名映射表（别名→上游模型，如 `gpt-4o-mini`→`qwen3-coder-30b`）。
- **用户 Key**：Key 表（名称、所有者、分组、sk 掩码+last4、状态、今日用量、创建时间，操作：停用/删除/导入）。
- **MCP 管理**：MCP 服务表（名称、类型 stdio/http、状态、工具数、分组可见性），工具数与用量 Tab。
- **告警与设置**：告警规则表（如"节点离线>60s""失败率>5%"，渠道：企业微信），
  全局设置（默认刷新间隔、数据保留期）。
- **安全设置**：管理员 2FA（TOTP 状态卡片）、登录会话表、审计日志摘要。
- **我的用量**：普通用户视角：我的 Key、今日/本月 Token、逐日趋势图。

## 交互与工程硬性要求

1. 自动刷新：默认开、默认 10s，可切 10/15/30/60，可暂停；刷新只替换数据
   （`chart.setOption`，容器不动），并更新"最近更新"时间与倒计时。
2. 所有筛选变化立即反映到当前页数据（mock 可按节点预生成，筛选时聚合/切换）。
3. 缺失指标一律渲染 `—`。
4. 数字用等宽/表格化数字字体；千分位分隔。
5. 无任何外部网络依赖（除字体外不准引 CDN），ECharts 用 `vendor/echarts.min.js`。
6. 单文件、零构建；直接用浏览器打开即可工作。
7. mock 数据要有"活"的感觉：每次刷新在当前值附近随机游走，趋势图滑动窗口推进。
